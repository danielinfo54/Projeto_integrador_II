# Documento de Requisitos

## 1. Introdução

O sistema tem como objetivo criar um canal organizado para o registro e acompanhamento de problemas e ocorrências no ambiente escolar. A plataforma permitirá que alunos, professores e funcionários comuniquem situações que necessitam de atenção da administração da escola, podendo realizar o relato de forma identificada ou anônima.

## 2. Problema

No ambiente escolar podem ocorrer problemas relacionados à estrutura, segurança, conservação, equipamentos e outras situações inadequadas. Quando não existe um meio adequado para comunicar essas ocorrências, pode haver dificuldade para que os responsáveis tenham conhecimento do problema e acompanhem as providências necessárias.

## 3. Objetivo do sistema

Desenvolver um sistema que permita registrar ocorrências e problemas encontrados na escola, possibilitando o envio de relatos identificados ou anônimos e o acompanhamento do andamento das providências.

## 4. Público-alvo

- Alunos;
- Professores;
- Funcionários da escola;
- Responsáveis pela administração escolar.

## 5. Requisitos Funcionais

### RF01 - Registrar ocorrência

O sistema deve permitir que o usuário registre uma ocorrência ou problema identificado no ambiente escolar.

### RF02 - Realizar relato anônimo

O sistema deve permitir que o usuário escolha realizar o relato de forma anônima.

### RF03 - Selecionar categoria

O sistema deve permitir selecionar uma categoria para a ocorrência.

### RF04 - Informar localização

O sistema deve permitir informar o local onde a ocorrência aconteceu.

### RF05 - Descrever a ocorrência

O sistema deve permitir inserir uma descrição detalhada da situação relatada.

### RF06 - Registrar data

O sistema deve registrar a data em que a ocorrência foi comunicada.

### RF07 - Consultar ocorrências

O sistema deve permitir aos responsáveis consultar as ocorrências registradas.

### RF08 - Atualizar status

O sistema deve permitir atualizar o status de uma ocorrência conforme o andamento das providências.

### RF09 - Registrar providências

O sistema deve permitir registrar as providências tomadas em relação à ocorrência.

### RF10 - Registrar resolução

O sistema deve permitir registrar quando uma ocorrência tiver sido resolvida.

## 6. Requisitos Não Funcionais

### RNF01 - Usabilidade

O sistema deve possuir uma interface simples, clara e fácil de utilizar.

### RNF02 - Organização

As ocorrências devem ser apresentadas de forma organizada, facilitando sua consulta e acompanhamento.

### RNF03 - Segurança

O sistema deve proteger as informações registradas e restringir o acesso às informações conforme o perfil do usuário.

### RNF04 - Privacidade

O sistema deve preservar a identidade dos usuários que optarem por realizar um relato anônimo.

### RNF05 - Acessibilidade

O sistema deve apresentar suas informações e funcionalidades de forma compreensível e acessível aos usuários.

## 7. Categorias de ocorrências

As ocorrências poderão ser classificadas nas seguintes categorias:

- Estrutura e infraestrutura;
- Segurança;
- Limpeza e conservação;
- Equipamentos;
- Situações inadequadas;
- Outros.

## 8. Status das ocorrências

As ocorrências poderão apresentar os seguintes status:

- Recebida;
- Em análise;
- Em providência;
- Resolvida.

## 9. Considerações

O sistema será desenvolvido como parte do Projeto Integrador II e terá como finalidade oferecer um canal organizado para comunicação de problemas e ocorrências no ambiente escolar, contribuindo para que as situações relatadas sejam analisadas e recebam as providências necessárias.
